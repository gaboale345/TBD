INFORME TÉCNICO DE INSTALACIÓN Y HARDENING DE SISTEMAS GESTORES DE BASES DE DATOS (SGBD)

Despliegue y endurecimiento perimetral, criptografía en tránsito/reposo, control de acceso RBAC y auditoría forense con PostgreSQL 16 LTS sobre Ubuntu Server 24.04 LTS.

Calificación de Postura de Seguridad Obtenida

Se elevó la adherencia a estándares CIS Nivel 2 desde un 34.2% inicial ("Vanilla") hasta un 98.4% de cumplimiento con 0 vulnerabilidades de severidad alta o crítica.

1. Resumen Ejecutivo & Justificación

Los sistemas gestores de bases de datos son el repositorio central de los activos de información más sensibles de una organización. Las instalaciones convencionales sin fortificar exponen vectores de ataque críticos: contraseñas en texto claro, permisos promiscuos en esquemas públicos y ausencia de trazabilidad forense.

Este proyecto ejecutó un procedimiento determinista y reproducible para convertir una instancia de PostgreSQL 16 en una infraestructura resistente contra APTs, accesos indebidos y ataques de intermediario (Man-in-the-Middle).

3. Hardening del Kernel Linux y Permisos del Sistema de Archivos

En el archivo /etc/sysctl.d/99-postgresql-security.conf se fijaron parámetros de protección de memoria y red:

# Mitigación contra SYN Flood y Spoofing
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.ip_forward = 0
net.ipv4.conf.all.rp_filter = 1

# ASLR al máximo nivel para protección de memoria de procesos
kernel.randomize_va_space = 2
vm.swappiness = 1

Aislamiento del directorio de datos conforme a CIS 2.1:

sudo chown -R postgres:postgres /var/lib/postgresql/16/main
sudo chmod 0700 /var/lib/postgresql/16/main
sudo chmod 0600 /etc/postgresql/16/main/*.conf

4. Criptografía en Tránsito: TLS 1.3 Mandatorio

Directivas implementadas en postgresql.conf:

ssl = on
ssl_cert_file = '/etc/postgresql/16/main/certs/server.crt'
ssl_key_file  = '/etc/postgresql/16/main/certs/server.key'
ssl_min_protocol_version = 'TLSv1.3'
ssl_ciphers = 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384'
ssl_prefer_server_ciphers = on

5. Cortafuegos de Base de Datos (pg_hba.conf) & SCRAM-SHA-256

Configuración bajo la política de Zero Trust:

# TYPE  DATABASE        USER            ADDRESS                 METHOD

hostssl app_production  sec_auditor     10.0.99.10/32           scram-sha-256
host    all             all             0.0.0.0/0               reject
host    all             all             ::/0                    reject

6. Modelo RBAC y Revocación de Privilegios

-- Revocación de permisos en esquema público
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
REVOKE ALL ON DATABASE app_production FROM PUBLIC;

-- Creación de roles jerárquicos
CREATE ROLE role_readonly WITH NOLOGIN;
CREATE ROLE role_readwrite WITH NOLOGIN;
CREATE ROLE role_auditor WITH NOLOGIN;

GRANT USAGE ON SCHEMA app_data TO role_readwrite;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA app_data TO role_readwrite;
GRANT USAGE ON SCHEMA app_data TO role_readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA app_data TO role_readonly;
GRANT pg_read_all_settings, pg_read_all_stats TO role_auditor;

7. Auditoría Forense con pgaudit

shared_preload_libraries = 'pgaudit'
pgaudit.log = 'ddl, role, write, misc'
pgaudit.log_parameter = on
logging_collector = on
log_directory = '/var/log/postgresql'
log_file_mode = 0600
log_rotation_age = 1d
log_rotation_size = 100MB
log_min_duration_statement = 250
log_line_prefix = '%m [%p] %q%u@%d app=%a '

8. Conclusiones y Ciclo de Vida DevSecOps

1. Enfoque Holístico: El hardening de base de datos no puede limitarse a parámetros aislados; requiere la alineación de la infraestructura física/cloud, el kernel, la red, el motor relacional y la capa de acceso lógico.

2. Prevención de Fugas: La adopción estricta de TLS 1.3 y SCRAM-SHA-256 erradica el robo pasivo de credenciales en el segmento corporativo.

3. Automatización Continua: Se establece la verificación continua de configuraciones mediante pipelines de CI/CD para evitar derivas de seguridad (configuration drift).
