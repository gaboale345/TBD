SECCIÓN 1 // INTRODUCCIÓN AL HARDENING

Concepto de Hardening y Elección Tecnológica

Por qué fortificar la base de datos y criterios de selección de PostgreSQL 16 y Ubuntu Server

INCIBE 2023

Definición de Hardening (Bastionado)

Un SGBD almacena activos críticos para cualquier entidad. Dejar su configuración por defecto genera riesgos innecesarios.

  • INCIBE (2023): "El bastionado permite identificar configuraciones seguras y aplicar medidas adicionales para mejorar la protección de un sistema".
  • Consiste en revisar parámetros y deshabilitar opciones superfluas.
Objetivo: Fortificar el servicio sin crear complejidades inmanejables.

Por qué PostgreSQL 16

Seleccionado por su madurez, transparencia en configuraciones y capacidades avanzadas de administración:

  • Gestión clara de usuarios, roles y privilegios sin superusuario obligatorio.
  • Filtro fino de clientes por IP y método en pg_hba.conf.
  • Soporte nativo para SCRAM-SHA-256 y cifrado TLS.
  • Registro nativo de eventos de conexión sin agentes externos.

Por qué Ubuntu Server 24.04 LTS

Plataforma Linux de nivel empresarial ampliamente documentada y con soporte extendido:

  • Seguridad por capas recomendada por Canonical (2026).
  • Aislamiento de permisos a nivel de sistema de archivos (0700).
  • Herramientas criptográficas estándar preinstaladas (openssl).
Stack: Ubuntu Server 24.04 LTS + PostgreSQL 16

SECCIÓN 3 // INSTALACIÓN DE POSTGRESQL

Instalación y Despliegue de PostgreSQL 16

Aprovisionamiento inicial de paquetes en Ubuntu Server, comprobación de servicios y primer acceso

Paso 1

Instalación de Paquetes

Actualización previa de repositorios e instalación del motor central y herramientas contribuidas:

$ sudo apt update
$ sudo apt upgrade -y
$ sudo apt install postgresql postgresql-contrib -y
Paso 2

Comprobación del Servicio

Verificación en Systemd para constatar que el demonio se encuentre activo y comprobar la versión instalada:

$ sudo systemctl status postgresql

Primer Acceso Administrativo

$ sudo -u postgres psql

# Conectado como usuario local postgres
MEDIDA DE HARDENING 4.1 // CANONICAL 2026

Medida 1: Mantener el Sistema Actualizado

Mitigación de vulnerabilidades conocidas y aplicación del modelo de seguridad por capas

Fundamento

Seguridad por Capas (Canonical 2026)

Ubuntu recomienda complementar la instalación con una estrategia defensiva en capas:

  • Actualizaciones periódicas de parches y kernel.
  • Administración estricta de cuentas de usuario del SO.
  • Protección y filtrado perimetral de red.
Ejecución

Procedimiento en Consola

Sincronización de repositorios oficiales y aplicación de correcciones disponibles:

$ sudo apt update
$ sudo apt upgrade -y

Impacto en la Seguridad

Las actualizaciones corrigen fallos de programación conocidos y reducen la probabilidad de explotación de vulnerabilidades públicas que ya cuentan con parches.

  • Parchea librerías criptográficas compartidas (OpenSSL).
  • Mejora la estabilidad y rendimiento del gestor.
MEDIDA DE HARDENING 4.2 // POSTGRESQL GLOBAL DEVELOPMENT GROUP 2026a

Medida 2: Restringir las Conexiones Permitidas

Control de acceso de clientes en pg_hba.conf, segmentación por subred y política de rechazo

pg_hba.conf

Mecanismo de Evaluación

Controla la autenticación de clientes evaluando en orden secuencial:

  • Tipo de conexión (local vs hostssl).
  • Base de datos de destino y usuario solicitante.
  • Dirección IP de origen y método de autenticación.
  • Se mantiene acceso local peer para postgres.
Reglas Oficiales

Reglas Aplicadas en pg_hba.conf

Se define acceso remoto exclusivo para app_user en app_practica desde 192.168.1.0/24 mediante TLS, rechazando todo lo demás:

# Archivo: /etc/postgresql/16/main/pg_hba.conf
local all postgres peer
hostssl app_practica app_user 192.168.1.0/24 scram-sha-256
host all all 0.0.0.0/0 reject
host all all ::/0 reject

Nota: Se utiliza coherentemente app_user para evitar inconsistencias con los roles de la base de datos.

MEDIDA DE HARDENING 4.3 // ALMACENAMIENTO DE CREDENCIALES

Medida 3: Usar Autenticación Segura (SCRAM-SHA-256)

Esquema criptográfico moderno para contraseñas y creación del usuario de aplicación

Estándar

Por qué SCRAM-SHA-256

Mecanismo moderno de desafío-respuesta (Salted Challenge Response Authentication Mechanism):

  • Evita almacenar contraseñas en esquemas antiguos como MD5 o texto claro.
  • Protege frente a ataques de fuerza bruta y diccionarios offline.
  • Recomendación oficial de PostgreSQL Global Development Group.
postgresql.conf

Configuración del Gestor

Se fuerza el cifrado estricto de contraseñas para todos los nuevos roles:

# En /etc/postgresql/16/main/postgresql.conf
password_encryption = 'scram-sha-256'

Creación de Base y Usuario

Sentencias SQL ejecutadas en la consola administrativa:

CREATE DATABASE app_practica;
CREATE USER app_user WITH PASSWORD 'ClaveDeEjemplo_2026!';

Aviso: Las contraseñas del informe son ejemplos didácticos.

MEDIDA DE HARDENING 4.4 // POSTGRESQL GLOBAL DEVELOPMENT GROUP 2026b

Medida 4: Aplicar el Principio de Mínimo Privilegio

Separación de roles para lectura y escritura, evitando privilegios administrativos en la aplicación

Mínimo Privilegio

Segregación Funcional

Un usuario de aplicación no debe tener permisos de superusuario:

  • Cada usuario recibe únicamente los permisos estrictamente necesarios.
  • Se definen roles abstractos con propiedad NOLOGIN.
  • Aislamiento entre operaciones de consulta y manipulación de datos.
Sentencias SQL

Creación y Concesión de Roles

Configuración de rol_lectura y rol_escritura, y vinculación al usuario app_user:

CREATE ROLE rol_lectura NOLOGIN;
CREATE ROLE rol_escritura NOLOGIN;

GRANT CONNECT ON DATABASE app_practica TO rol_lectura, rol_escritura;
GRANT USAGE ON SCHEMA public TO rol_lectura, rol_escritura;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO rol_lectura;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO rol_escritura;

GRANT rol_escritura TO app_user;
MEDIDA DE HARDENING 4.4 (CONT.) // CONTROL DE ESQUEMAS

Medida 4 (Cont.): Saneamiento del Esquema Public

Revocación del privilegio de creación a PUBLIC para impedir la creación indiscriminada de objetos

Vulnerabilidad

El Riesgo del Esquema Public

En instalaciones por defecto de PostgreSQL, cualquier usuario con acceso puede crear tablas y objetos en el esquema public.

  • Riesgo de colisión de nombres y consumo no controlado de espacio.
  • Un usuario comprometido podría crear funciones u objetos maliciosos.
Sentencia SQL

Revocación del Privilegio CREATE

Se elimina el privilegio de creación para el pseudo-rol global PUBLIC:

-- En la base de datos app_practica:
REVOKE CREATE ON SCHEMA public FROM PUBLIC;

Beneficio Obtenido

Solo administradores autorizados pueden alterar el esquema de datos.

  • El usuario app_user queda restringido exclusivamente a consultar y manipular datos.
  • Se mantiene la integridad y orden estructural de la base de datos.
MEDIDAS DE HARDENING 4.5 Y 4.6 // PERMISOS FÍSICOS Y CIFRADO

Medidas 5 y 6: Protección de Archivos y Cifrado TLS

Permisos restrictivos en el sistema de archivos (0700/0600) y certificados SSL/TLS para red

Medida 4.5

Protección de Archivos de Datos

Los archivos físicos contienen la información sensible. Se asegura propiedad exclusiva y permisos restrictivos:

$ sudo chown -R postgres:postgres /var/lib/postgresql/16/main
$ sudo chmod 0700 /var/lib/postgresql/16/main

Impide que otros usuarios del SO puedan leer los ficheros de datos.

Medida 4.6

Habilitar Conexiones Cifradas con TLS

Cifra el tráfico entre cliente y servidor. Generación de certificado autofirmado X.509 para laboratorio y configuración en PostgreSQL:

$ sudo openssl req -new -x509 -nodes -days 365 -newkey rsa:2048 \
-keyout /etc/postgresql/16/main/server.key \
-out /etc/postgresql/16/main/server.crt
$ sudo chown postgres:postgres /etc/postgresql/16/main/server.*
$ sudo chmod 0600 /etc/postgresql/16/main/server.key

# En postgresql.conf:
ssl = on
ssl_cert_file = '/etc/postgresql/16/main/server.crt'
ssl_key_file = '/etc/postgresql/16/main/server.key'
MEDIDAS DE HARDENING 4.7 Y 4.8 // REGISTROS Y RESPALDOS

Medidas 7 y 8: Registros de Actividad y Copia de Seguridad

Monitoreo nativo de conexiones/desconexiones y respaldo lógico periódico con pg_dump

Medida 4.7

Registros Básicos de Actividad

Habilita el colector de logs nativo para registrar conexiones y desconexiones sin agentes adicionales:

# En /etc/postgresql/16/main/postgresql.conf
logging_collector = on
log_connections = on
log_disconnections = on
log_line_prefix = '%m [%p] %u@%d '
Medida 4.8

Copia de Seguridad (pg_dump)

El hardening no evita todos los incidentes. Se genera un respaldo lógico en formato personalizado:

$ pg_dump -U postgres -F c \
-d app_practica \
-f app_practica.backup

Almacenamiento del Respaldo

Directivas clave de resiliencia según el informe:

  • Guardar fuera del directorio principal de PostgreSQL.
  • De ser posible, trasladar a otro equipo o soporte de almacenamiento externo.
