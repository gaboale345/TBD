FASE 1 // AISLAMIENTO DE INFRAESTRUCTURA & KERNEL

Hardening del Kernel Linux y Sandboxing Systemd

Fortificación del subsistema operativo para prevenir ataques de denegación de servicio y desbordamiento de memoria

/etc/sysctl.d/99-postgresql-security.conf 
# 1. Mitigación de ataques de Denegación de Servicio TCP SYN Flood
net.ipv4.tcp_syncookies = 1

# 2. Deshabilitar redirección ICMP y evitar alteración de enrutamiento
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.ip_forward = 0

# 3. Mitigación estricta de IP Spoofing (Reverse Path Filtering)
net.ipv4.conf.all.rp_filter = 1

# 4. ASLR al nivel máximo (2) contra ataques de corrupción de memoria
kernel.randomize_va_space = 2

# 5. Restringir swappiness para evitar volcado de memoria a disco
vm.swappiness = 1

Permisos en $PGDATA (CIS 2.1)

Máscara octal estricta para impedir lectura por usuarios del sistema no autorizados.

chmod 0700 /var/lib/postgresql/data chmod 0600 /etc/postgresql/*.conf chown -R postgres:postgres /var/lib/postgresql

Sandboxing Nativo en Systemd

  • ProtectSystem=strict (Archivos en Read-Only)
  • NoNewPrivileges=true (Bloqueo de binarios SUID)
  • PrivateTmp=true (Espacio /tmp aislado)
  • ProtectHome=true (Sin acceso a home de usuarios)
FASE 2 // CRIPTOGRAFÍA PERIMETRAL

Cifrado en Tránsito con TLS 1.3 Mandatorio

Erradicación absoluta del texto plano y protección contra ataques de degradación mediante suites criptográficas de última generación

/etc/postgresql/16/main/postgresql.conf (Sección SSL) 
# Habilitación forzosa de SSL
ssl = on
ssl_cert_file = '/etc/postgresql/16/main/certs/server.crt'
ssl_key_file  = '/etc/postgresql/16/main/certs/server.key'

# CIS Benchmark 4.1: Forzar versión mínima TLS 1.3
ssl_min_protocol_version = 'TLSv1.3'

# Ciphers de alta seguridad (Cifrado autenticado AEAD con GCM)
ssl_ciphers = 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384'
ssl_prefer_server_ciphers = on
ssl_ecdh_curve = 'prime256v1'

Propiedades Criptográficas

  • Perfect Forward Secrecy (PFS): Claves efímeras por sesión garantizan que la captura de tráfico histórico no pueda ser descifrada.
  • Certificados X.509: Claves RSA de 4096 bits o Ed25519 con permisos 0600.
  • Protección MitM: Verificación de integridad mutua.

FASE 3 // AUTENTICACIÓN & CORTAFUEGOS DE APLICACIÓN

Autenticación SCRAM-SHA-256 y Cortafuegos pg_hba.conf

Sustitución de mecanismos obsoletos y política de Cero Confianza (Zero Trust) con denegación por defecto

SCRAM-SHA-256 vs Métodos Heredados

✕
trust / password Acceso sin clave o en texto plano sin hash.
⚠
md5 (Deprecado) Vulnerable a colisiones y tablas rainbow.
✓
scram-sha-256 (Mandatorio) Salt aleatorio de 32 bytes, 4096 iteraciones. El servidor jamás almacena la clave en claro.
/etc/postgresql/16/main/pg_hba.conf (Reglas Zero Trust) 
# TYPE  DATABASE        USER            ADDRESS                 METHOD

# 1. Superusuario postgres: EXCLUSIVO local mediante UNIX socket peer
local   all             postgres                                peer

# 2. Conexiones locales de herramientas de sistema con SCRAM
local   all             all                                     scram-sha-256

# 3. Aplicaciones de negocio: TLS Mandatorio (hostssl) y Subred Restringida
hostssl app_production  app_backend     10.0.50.0/24            scram-sha-256
hostssl app_production  sec_auditor     10.0.99.10/32           scram-sha-256

# 4. RECHAZO POR DEFECTO (Cero conexiones no declaradas)
host    all             all             0.0.0.0/0               reject
host    all             all             ::/0                    reject
FASE 4 // CONTROL DE ACCESO LÓGICO & PRIVILEGIOS

Matriz de Roles RBAC y Saneamiento del Esquema Public

Aplicación estricta del Principio de Menor Privilegio y aislamiento de dominios transaccionales

Saneamiento Inmediato (CIS 5.1)

Eliminación de la brecha histórica del esquema público:

REVOKE CREATE ON SCHEMA public FROM PUBLIC; REVOKE ALL ON DATABASE app_prod FROM PUBLIC; REVOKE EXECUTE ON FUNCTION pg_read_file(text) FROM PUBLIC;
rbac_security_model.sql 
-- 1. Roles grupales sin acceso de login directo (NOLOGIN)
CREATE ROLE role_readonly WITH NOLOGIN;
CREATE ROLE role_readwrite WITH NOLOGIN;
CREATE ROLE role_auditor WITH NOLOGIN;

-- 2. Concesión de privilegios mínimos en el esquema de aplicación
GRANT USAGE ON SCHEMA app_data TO role_readwrite;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA app_data TO role_readwrite;

-- 3. Rol de sólo lectura para reportes y Business Intelligence
GRANT USAGE ON SCHEMA app_data TO role_readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA app_data TO role_readonly;

-- 4. Rol auditor: acceso exclusivo a métricas y configuraciones del motor
GRANT pg_read_all_settings, pg_read_all_stats TO role_auditor;
FASE 5 // TRAZABILIDAD & MONITOREO CONTINUO

Auditoría Forense con pgaudit y Logging Inmutable

Captura estructurada de eventos DDL, modificaciones de roles y centralización segura hacia plataforma SIEM

pgaudit & postgresql.conf (Trazabilidad Forense) 
# Precarga de extensión de auditoría certificada
shared_preload_libraries = 'pgaudit'

# Clases de eventos auditados: DDL, Roles, Escrituras críticas y Misceláneos
pgaudit.log = 'ddl, role, write, misc'
pgaudit.log_catalog = off
pgaudit.log_parameter = on   # Captura parámetros de sentencias preparadas

# Parámetros del subsistema de logs del motor
logging_collector = on
log_directory = '/var/log/postgresql'
log_file_mode = 0600         # Permisos exclusivos del usuario de base de datos
log_rotation_age = 1d
log_rotation_size = 100MB
log_connections = on
log_disconnections = on
log_min_duration_statement = 250  # Alerta en queries lentas > 250ms
